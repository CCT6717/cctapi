# 精准尝试链路可观测性设计

## 目标

基于现有 `attempt_events` 和进程内尝试指标，为 `/fallback/status` 的“运行数据”提供精确、脱敏的失败聚合与最近路由链路，替换当前从供应商切换日志推算 Top 失败模型/渠道的近似逻辑。

本阶段保持现有成功事件不写入 SQLite 的原则，不改变路由、计费、重试、冷却或降权行为。

## 范围

本阶段包含：

- 最近 1 小时真实上游失败、模型级 429、不可回退错误和能力误判的精确聚合。
- 按部署、供应商、真实模型、错误类别和结果类型展示 Top 项。
- 单独统计本地跳过事件，避免把额度、并发或模型冷却跳过误算为上游失败。
- 展示进程内最近完整请求链路，包括跳过、真实尝试、模型轮换、供应商回退和最终成功。
- 管理员接口权限、查询上限、固定安全字段和中文后台展示。
- 桌面端、移动端、并发和脱敏测试。

本阶段不包含：

- 持久化所有成功事件。
- 新建独立的 connectivity-test 页面。
- 修改供应商降权算法或路由排序。
- 新增持久化告警生命周期。现有 L2/L3 降权状态继续由运行状态接口展示；基于精准聚合的告警策略作为后续独立切片。
- 多实例共享最近链路。最近链路明确为单进程内存诊断，重启后清空。

## 方案比较

### 方案 A：返回原始事件，由前端聚合

实现最少，但会把大量事件传给浏览器，聚合口径容易在不同页面漂移，也增加敏感字段误暴露和移动端性能风险，不采用。

### 方案 B：只做 SQLite 聚合

失败排名准确且可跨重启，但因为成功事件按现有原则不落库，无法展示最终成功节点，也无法还原完整请求链路，不采用。

### 方案 C：SQLite 聚合 + 有界进程内链路

SQLite 负责最近 1 小时精确失败聚合；所有尝试在进入现有持久化判定前，同时写入线程安全的有界内存环形缓冲区。这样既不增加常规成功写放大，又能展示近期完整链路。采用此方案。

## 后端设计

### 失败聚合

在 `fallback` 包新增只读聚合边界，固定查询最近 1 小时：

- `failure`、`model_rate_limited`、`non_fallbackable`、`model_capability_false_positive` 且 `upstream_attempt_index > 0` 计入真实上游失败。
- `skipped_unavailable`、`skipped_quota`、`skipped_concurrency`、`skipped_channel`、`skipped_model_state` 单独计入跳过统计。
- 聚合只返回计数、最后发生时间、部署 ID、供应商、虚拟模型、真实模型、结果类型、HTTP 状态码和安全错误类别。
- 排名先按计数降序，再按最后发生时间降序，最后按稳定字符串键排序。
- 每个 Top 列表最多 5 项，错误类别和结果类型最多 10 项。

聚合查询不得返回原始上游正文、请求正文、响应正文、Authorization、API key、token、cookie 或数据库内部错误。

### 最近完整链路

在 `RecordAttemptEventIfWorthy` 的统一入口记录所有尝试到进程内有界缓冲区，然后继续执行原有持久化规则：

- 最多保留 1000 个尝试事件。
- 快照最多返回最近 20 个请求，每个请求最多 50 个步骤。
- 使用互斥锁保护写入和快照；快照必须深拷贝，排序在锁外完成。
- 请求按最近步骤时间倒序，步骤按 `plan_index`、`upstream_attempt_index`、创建时间和 ID 稳定排序。
- 成功、失败、跳过、模型级 429 和不可回退结果均可出现。
- 重启后链路清空，接口明确返回 `scope: process`。

### 管理接口

在现有 fallback 管理员路由组增加：

```text
GET /api/fallback/attempt-observability
```

响应固定为：

```json
{
  "success": true,
  "data": {
    "generated_at": "RFC3339",
    "failure_window_seconds": 3600,
    "failure_event_count": 0,
    "skip_event_count": 0,
    "top_deployments": [],
    "top_providers": [],
    "top_models": [],
    "error_categories": [],
    "outcomes": [],
    "recent_chains": [],
    "recent_chain_scope": "process"
  }
}
```

数据库查询失败时返回结构化 JSON 和脱敏消息 `attempt observability unavailable`，服务端使用项目日志记录具体错误。接口不接受任意 SQL 窗口或 limit 参数，避免无界查询。

## 前端设计

`useFallbackPage` 在运行数据面板的现有刷新周期中获取新接口，失败时保留上一次成功快照并显示紧凑错误提示，不影响其他运行数据。

`MetricsPanel` 调整为：

- “Top 失败模型/渠道”改为“精准失败诊断”，明确标注“最近 1 小时真实尝试事件”。
- 展示 Top 部署、Top 真实模型、Top 供应商和错误类别。
- 跳过统计独立展示，不与上游失败混合。
- 最近链路使用紧凑纵向步骤列表，显示虚拟模型、部署、真实模型、结果、状态码和耗时。
- 请求 ID 仅用于管理员追踪，不作为 URL 或可执行内容。
- 所有用户文案使用中文，保留 HTTP、RPM、token、model 等必要技术缩写。
- 移动端采用单列，不允许链路内容造成横向滚动。

现有切换日志页面继续保留，但不再作为运行数据页 Top 失败排名的数据源。

## 数据与安全边界

- 持久化失败数据继续遵循 7 天保留期。
- 聚合窗口固定 1 小时；最近链路只保存在当前进程。
- API 类型使用显式响应结构，不直接序列化数据库模型。
- 错误类别必须来自现有枚举安全字符串。
- 供应商和模型字段使用现有目录标识，不拼接原始错误正文。
- 管理接口沿用现有管理员中间件，不向公开 `/metrics` 暴露请求链路。

## 测试策略

### 后端

- 先写失败测试，再实现聚合和环形缓冲区。
- 验证真实失败与跳过事件分开统计。
- 验证模型级 429、非 429 rate-limit-shaped 错误和不可回退错误的口径。
- 验证稳定排序、固定窗口、Top 上限和空数据库。
- 验证完整请求链路顺序、1000 事件上限、20 请求上限和深拷贝。
- 验证并发记录、快照和重置通过 race test。
- 验证响应不含密钥、原始错误正文或请求/响应内容。
- 验证管理员权限和结构化失败响应。

### 前端

- Vitest 验证新接口加载、失败保留旧快照和精准数据映射。
- 组件测试验证中文诊断、空状态、错误状态、429 与跳过结果展示。
- Playwright 验证桌面端和 Mobile Chrome 单列布局、无横向滚动。

### 完整验收

- Go focused tests、全包测试、vet、race 和 build。
- ESLint、Vitest、Vite、Storybook 和 Playwright。
- 使用计划投入生产的凭证进行 30 至 60 分钟 paced soak；若当前没有目标生产凭证，明确记录为外部阻塞，不用匿名免费额度冒充生产容量验收。
- paced soak 覆盖 Chat Completions、Responses、stream 和 tools，核对链路、聚合、降权与恢复证据并执行脱敏扫描。

## 验收标准

- 后台 Top 失败排名不再依赖切换日志。
- 同一请求的 Kilo 模型轮换和跨供应商回退可以按顺序查看，且最终成功节点可见。
- 本地跳过不会污染真实上游失败排名。
- API 和证据中没有密钥、token、原始上游错误正文或请求/响应正文。
- 并发测试无数据竞争，移动端无横向溢出。
- 所有质量门禁和独立代码审查通过后，才允许创建合并 PR。
