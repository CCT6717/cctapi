# cctapi 发布门禁

> 文档状态：草稿
>
> 能力状态：TARGET（合并并完成首个 R1-R4 记录后转为 CURRENT）

## 1. 文档 Gate 与发布 Gate

G3～G6 只证明架构文档完成审核和归档：

- G3：高层架构文档审核。
- G4：系统设计和 User Story 审核。
- G5：部署与安全设计审核。
- G6：交付文档归档审核。

任何 G Gate 都不能单独证明代码可发布。

## 2. 发布 Gate

| Gate | 必须证据 | 失败处理 |
|------|----------|----------|
| R1 独立代码审查 | 对目标 SHA 的 findings；无未处理 P0～P2 | 停止发布并修复 |
| R2 自动化验证 | GitHub CI 对目标 SHA 全绿；Go test/race/vet/build、前端 lint/Vitest/Vite/Storybook、Playwright、仓库检查、govulncheck | 不得使用旧 CI 或其他 SHA 代替 |
| R3 真实运行验收 | 目标二进制在 `3008`；Chat Completions、Responses、stream、tools；模型轮换、供应商回退、冷却恢复 | 回滚并保留脱敏失败证据 |
| R4 证据与版本确认 | 精确 SHA、CI URL、二进制构建时间、运行端口、脱敏证据文件、无临时 token | 清理凭据后重新审核 |

## 3. 判定规则

- 四个 R Gate 必须针对同一个目标 SHA。
- 本地测试通过不能代替 R2 CI。
- 源码审阅不能代替 R3 真实协议验收。
- 历史验收只能作为回归参考，不能证明新 SHA 已通过。
- 外部免费配额耗尽应记录为外部阻塞，不能伪报为本地回归或验收通过。
- 验收证据只保存固定错误类别、状态码、模型/供应商标识和时间，不保存 key、Token、密码或原始上游错误正文。

## 4. 发布记录模板

```text
目标 SHA:
R1 审查结论:
R2 CI URL / conclusion:
R3 运行版本 / 端口 / 协议结果:
R4 证据路径 / 凭据清理结果:
已知外部限制:
最终结论: PASS / BLOCKED
```

只有四项证据齐全且最终结论为 `PASS`，才能更新 `AGENTS.md` 为“release-ready”。
